❯ and should i also run the worker functions right with the fastapi server?     
● Yes — the FastAPI server alone only handles API requests. The advisory
  pipeline needs three workers polling in the background:

  1. advisory_worker — picks up queued jobs, runs the 7-stage pipeline (scrape,
  rank, deliver)
  2. advisory_cycle_worker — polls trip_advisory_state every 30s, fires
  location_trigger jobs for active trips
  3. advisory_ignore_sweep_worker — polls every 10min, expires unacted
  advisories, pauses brain after 3 ignores

  For local testing, run them in separate terminals alongside the server:

  # Terminal 1: API server
  cd backend && ./venv/Scripts/python.exe -m uvicorn app.main:app --reload

  # Terminal 2: advisory job processor
  cd backend && ./venv/Scripts/python.exe -m app.workers.advisory_worker

  # Terminal 3: cycle worker (triggers advisory jobs during live trips)
  cd backend && ./venv/Scripts/python.exe -m app.workers.advisory_cycle_worker

  # Terminal 4 (optional): ignore sweep
  cd backend && ./venv/Scripts/python.exe -m
  app.workers.advisory_ignore_sweep_worker

  The cycle worker is the critical one — without it, starting a live session
  seeds the brain and sets it to active, but no location_trigger jobs get
  created. The ignore sweep is less urgent for testing.

  For the flow to work end-to-end you also need OPENROUTER_API_KEY set in
  backend/.env (for Reddit scrape + LLM extraction). BRIGHTDATA_WS_ENDPOINT is
  optional — GMaps stage skips gracefully without it.
